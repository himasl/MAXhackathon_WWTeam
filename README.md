# Маршрут

Чат-бот MAX с мини-приложением, который строит студенту персональный маршрут действий после переезда в другой регион на учёбу: регистрация, поликлиника, проезд, меры поддержки — с причиной появления каждого шага, документами, рекомендуемым сроком и официальным источником.

Трек хакатона «Забота о людях», направление «Интеграция новых жителей».

> «Маршрут» — не государственный сервис. Он не принимает юридически значимых решений и не гарантирует право на льготу. Решение о включении шага принимает детерминированный движок правил, а не LLM.

## Problem

Студент, впервые переехавший в другой регион, собирает информацию из разных источников: сайт вуза, Госуслуги, региональные порталы, МФЦ, советы в чатах. Ему приходится самостоятельно понимать, какие действия относятся именно к нему (общежитие или съёмная квартира, очная или заочная форма, есть ли регистрация), в каком порядке их выполнять, какие документы нужны и что уже сделано.

Формула проблемы: *студент-первокурсник, переехавший в другой регион, хочет быстро закрыть обязательные дела после переезда, но сталкивается с разрозненной информацией и не понимает, что относится к нему и что делать дальше, из-за чего откладывает регистрацию и прикрепление к поликлинике и упускает доступные льготы.*

## Solution

1. В боте пользователь нажимает «Открыть маршрут» — открывается мини-приложение.
2. Отвечает на 6 вопросов (регион, возраст, форма обучения, жильё, регистрация, поликлиника).
3. Движок правил отбирает шаги сценария, подходящие именно ему, и строит маршрут.
4. У каждого шага: «Почему этот шаг появился?», что сделать, документы, куда обратиться, рекомендуемый срок, официальный источник с датой проверки.
5. Пользователь отмечает шаги выполненными и видит прогресс.
6. Бот присылает следующий шаг, напоминает о приближении рекомендуемого срока и поздравляет с завершением. Кнопка в сообщении открывает нужный шаг в мини-приложении (deep link).

Чем это отличается от каталога жизненных ситуаций на Госуслугах: маршрут персональный (шаги отбираются по ответам), в нём есть прогресс и напоминания в мессенджере, а региональные шаги (проезд в Москве, Санкт-Петербурге, Казани) собраны в одном месте со ссылками на официальные источники.

## Target audience

Студенты — граждане РФ, переехавшие в другой регион для обучения, в первые недели после заселения. Приоритетный сегмент — первокурсники очной формы, живущие в общежитии или снимающие жильё.

## User scenario

```text
/start в боте → «Открыть маршрут» → Welcome → 6 вопросов → маршрут
→ шаг: причина, документы, источник → «Отметить выполненным» → следующий шаг
→ … → «Маршрут завершён»
Параллельно бот: «Ваш маршрут готов», «Следующий шаг», напоминание о сроке, поздравление.
```

## Architecture

Модульный монолит: один процесс FastAPI отдаёт API, собранное мини-приложение и принимает события бота.

```text
MAX (бот) ──webhook / long polling──┐
MAX (Mini App, React) ──HTTPS──────┐│
                                   ▼▼
                    FastAPI (app.main)
        ┌─────────────┬───────────┴──────┬──────────────────┐
     auth          routes API        bot handler       notifications
 (initData HMAC)       │                 │                   │
                  RouteService ──► RouteGenerator ──► Rule Engine
                       │            (чистая логика)
                  Repositories (SQLAlchemy async) ──► PostgreSQL
                                                       ▲
                  data/scenarios/*.json ──seed──────────┘
        integrations/max/MAXClient ◄── MessageSender (протокол)
```

- Доменная логика (`rules`, `scenarios/engine.py`) не зависит от FastAPI, PostgreSQL и MAX.
- Бизнес-сервисы не вызывают MAX напрямую: `NotificationService` работает через протокол `MessageSender`, реализация — `MaxMessageSender`.
- Сценарии, правила, документы и источники — данные в `data/scenarios/*.json`, а не код.

Подробнее: [`docs/architecture.md`](docs/architecture.md).

## Technology stack

- Backend: Python 3.13, FastAPI, Pydantic v2, SQLAlchemy 2 (async), Alembic, asyncpg, httpx.
- Frontend: React 19, TypeScript, Vite, MAX Bridge (`max-web-app.js`).
- БД: PostgreSQL 16+.
- Инфраструктура: Docker, Docker Compose; деплой — Render (Docker web service) + Neon (PostgreSQL).
- Качество: pytest, ruff, mypy (strict).

## Local development

Требования: Python 3.13, Node.js 22, PostgreSQL.

```bash
# backend
cd backend
python3.13 -m venv .venv
.venv/bin/pip install -r requirements.txt -e '.[dev]'
export DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/marshrut
.venv/bin/alembic upgrade head
.venv/bin/python -m app.scenarios.seed
DEV_AUTH_ENABLED=true .venv/bin/uvicorn app.main:app --reload

# frontend (в другом терминале)
cd frontend
npm ci
VITE_API_URL=http://localhost:8000 npm run dev   # http://localhost:5173
```

В браузере вне MAX вход выполняется за development-пользователя `DEV_MAX_USER_ID` (только при `DEV_AUTH_ENABLED=true` и `APP_ENV` ≠ `production`).

## Docker

```bash
cp .env.example .env        # при желании вписать MAX_BOT_TOKEN
docker compose up --build   # http://localhost:8000
```

- Сервисы: `postgres` (с healthcheck) и `backend` (ждёт готовности БД, применяет миграции, загружает сценарий, запускает API и отдаёт мини-приложение).
- Порт: `8000` (API, мини-приложение, `/docs`). Postgres наружу не публикуется.
- Если в `.env` задан `MAX_BOT_TOKEN`, бот работает локально через long polling — публичный адрес не нужен.
- Остановить: `docker compose down`. Сбросить данные: `docker compose down -v`. Перезапустить: `docker compose up -d`.
- Сборка образа занимает около 1–2 минут.

## Environment variables

Полный список с комментариями — в [`.env.example`](.env.example).

| Переменная | Назначение |

| `TEST_ACCESS_TOKENS` | Тестовые токены проверяющих: `token:max_user_id,…` |
| `REMINDERS_ENABLED`, `REMINDER_INTERVAL_SECONDS` | Напоминания о сроках |
| `DEV_AUTH_ENABLED`, `DEV_MAX_USER_ID` | Вход без MAX для локальной разработки |

## MAX configuration

- Бот: `@t818_hakaton_max_bot`, токен выдан организаторами и задаётся только переменной `MAX_BOT_TOKEN`.
- Мини-приложение: в настройках бота на платформе MAX для партнёров указывается URL деплоя (`PUBLIC_URL`). Кнопки `open_app` в сообщениях бота открывают его; `payload` вида `step_<id>` открывает конкретный шаг.
- События: в production — webhook `POST {PUBLIC_URL}/max/webhook` с проверкой `X-Max-Bot-Api-Secret`, подписка создаётся автоматически при старте; локально — long polling `GET /updates`.
- Авторизация мини-приложения: frontend передаёт `window.WebApp.initData` в `POST /api/v1/auth/max`, backend проверяет HMAC-SHA256 подпись токеном бота и срок `auth_date`, после чего выдаёт токен доступа. `user_id` от клиента не принимается.
- TLS: сертификат `platform-api2.max.ru` выпущен НУЦ Минцифры, поэтому `MAXClient` доверяет публичным CA и сертификатам из `backend/certs/` (подробности — в [`backend/certs/README.md`](backend/certs/README.md)).

## API

Все методы, кроме `/health`, — под `/api/v1`. Полное описание — [`openapi.yaml`](openapi.yaml) (OpenAPI 3.1, генерируется `python backend/scripts/export_openapi.py`).

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Доступность |
| POST | `/api/v1/auth/max` | Обмен MAX initData на токен |
| GET | `/api/v1/me` | Текущий пользователь |
| GET / PUT | `/api/v1/profile` | Ответы онбординга |
| POST | `/api/v1/routes` | Построить маршрут (201) |
| GET | `/api/v1/routes/current` | Текущий маршрут и прогресс |
| GET | `/api/v1/routes/{route_id}/steps/{step_id}` | Карточка шага |
| POST | `/api/v1/routes/{route_id}/steps/{step_id}/complete` | Выполнить шаг |
| POST | `/api/v1/routes/{route_id}/steps/{step_id}/reopen` | Вернуть шаг в работу |
| POST | `/api/v1/routes/{route_id}/remind` | Прислать следующий шаг в чат MAX |

Авторизация: `Authorization: Bearer <token>`. Ошибки — единый формат `{"error": {"code": "ROUTE_NOT_FOUND", "message": "…"}}`, коды 401/404/409/422/503; stack trace наружу не отдаётся.

Проверка всех обязательных методов против живого сервера:

```bash
pip install pyyaml
python tools/run_data_api.py --base-url https://marshrut-tf5o.onrender.com --token <тестовый токен>
```

## Data

- Сценарий `data/scenarios/student_relocation_v1.json`: шаги, правила, документы, источники. При старте `python -m app.scenarios.seed` загружает новые версии сценариев в БД (идемпотентно, опубликованная версия не переписывается — маршруты на неё ссылаются).
- Правила валидируются при загрузке: неизвестные поля, неверные типы значений и неизвестные значения перечислений отклоняются.
- Персональные данные: хранится только `max_user_id` и ответы онбординга (возраст, регион, форма обучения, тип жилья, наличие регистрации и прикрепления). ФИО, паспортные и медицинские данные не собираются. Токены и персональные данные не логируются.

## Mock data

Каждый источник помечен типом, и интерфейс это показывает:

| Тип | Что значит | Пример |
|---|---|---|
| `OFFICIAL` | Ссылка на официальный сайт с датой проверки | Госуслуги, mos.ru, gov.spb.ru, kazantransport.ru, ФОМС |
| `MOCK` | Демонстрационная памятка, официальный источник не внесён; в интерфейсе — «Демонстрационные данные» | поддержка в вузе, проезд в «другом регионе» |

Тексты шагов — памятки, составленные командой; порядок действий нужно сверять с официальным источником шага. Интеграции с государственными системами в MVP нет и она не имитируется.

## Known limitations

- Данные по регионам — демонстрационный набор (Москва, Санкт-Петербург, Татарстан, «другой регион»). Ссылки на официальные источники проверены 23.09.2026, тексты шагов — памятки команды.
- Интеграций с государственными ИС нет: сервис ведёт пользователя к официальной услуге, но не подаёт заявления за него.
- Напоминания отправляются фоновым циклом внутри процесса (раз в час), без отдельного планировщика.
- На бесплатном тарифе Render сервис засыпает без трафика; для проверки его держит в активном состоянии внешний пинг `/health` (см. [`docs/deploy.md`](docs/deploy.md)).
- Основная версия интерфейса — на русском; тексты вынесены в данные сценария, что допускает локализацию.

## Scaling

Ядро одинаково для всех контекстов: `UserContext` → Rule Engine → Scenario → Route → прогресс и уведомления. Меняются только данные:

- **Новый регион** — добавить шаги с правилом `region_code` и официальные источники в JSON сценария; код не меняется.
- **Новая категория пользователей** — новый сценарий (например, `foreign_student_v1` для иностранного студента: миграционный учёт, ДМС, языковая версия) и новые поля анкеты.
- **Вуз как партнёр** — вуз ведёт свой набор шагов (общежитие, профком, стипендии) и получает ссылку на бота для первокурсников.
- **Пилот** — первокурсники одного-двух вузов Казани в сентябре: ссылка на бота в чатах групп и при заселении в общежитие. Метрики: доля завершивших маршрут, время до регистрации и прикрепления к поликлинике, доля открытых напоминаний, повторные обращения в деканат по этим вопросам.
- **Дальше** — интеграции с официальными API (при наличии), автоматическая проверка актуальности источников, админ-инструмент для редакторов сценариев.
