# Сопровождение «Маршрута»

Памятка для команды: как обновлять данные, разбирать обращения и ошибки, выкатывать и откатывать версии. Код менять для этого почти никогда не нужно — данные лежат в `data/`.

## Где что лежит

| Что | Файл | Когда меняется |
|---|---|---|
| Шаги, правила, документы, источники | `data/scenarios/*.json` | новые шаги, правки текстов, новый вуз-партнёр |
| МФЦ, фонд ОМС, студенческий проезд по регионам | `data/regional_services.json` | сменился сайт, появилась льгота, новый регион |
| Непроверенные региональные ссылки | `data/regional_candidates.json` | после проверки переносятся в основной файл |
| Раздел «Если что-то пошло не так» | `data/help.json` | телефоны, ссылки, тексты помощи |
| Вузы и колледжи | `data/universities.json` | новый вуз, «Часто выбирают» |
| Регионы | `data/regions.json` | почти никогда |

Данные загружаются при старте сервиса (`python -m app.scenarios.seed`), отдельной админки нет.

## Обновить данные

1. Поправьте JSON. Для региональной записи достаточно `organization`, `url` и `checked_at`; для проезда — ещё `city`, `title`, `summary`, `documents`.
2. Если менялись сценарии или `regional_services.json` — поднимите `version` в JSON сценария. Опубликованная версия в БД не переписывается: без новой версии правка не дойдёт до прода. Тест `tests/test_scenario_versions.py` это ловит; после повышения версии обновите отпечатки:
   ```bash
   cd backend && python -m tests.test_scenario_versions
   ```
3. Проверьте, что ссылки открываются (из российской сети — многие региональные сайты недоступны из-за рубежа):
   ```bash
   python3 tools/check_sources.py              # региональные источники
   python3 tools/check_sources.py --help-links # раздел «Помощь»
   python3 tools/check_sources.py --candidates --promote  # перенести открывшиеся кандидаты
   ```
   Скрипт проверяет только, что страница отвечает. Что сайт официальный, а текст шага совпадает со страницей, проверяет человек.
4. Перед push прогоните тесты (`cd backend && pytest -q`), затем `git push` — Render выкатит новую версию автоматически.

## Отзывы пользователей «Сообщить о неточности»

- Под каждым шагом есть тихая ссылка «Сообщить о неточности»: «информация устарела», «шаг мне не подходит», «другое» и комментарий.
- Отзыв сохраняется в таблице `step_reports`. Раз в день в 10:00 по Москве бот присылает тем, чьи MAX ID указаны в `SUPPORT_MAX_USER_IDS`, одну сводку новых отзывов: шаг, сценарий и версия, регион, ссылки источников, комментарий. По понедельникам в ту же сводку добавляется список источников, проверенных больше 90 дней назад. Повтор того же отзыва о том же шаге за сутки не сохраняется.
- Та же группа получает сообщение об ошибке 500 с кодом для поддержки (не чаще раза в 10 минут) и может запросить метрики командой `/stats`.
- Счётчик отзывов — `steps.reported` в `GET /api/v1/stats`.

## Панель команды

Вкладка «Команда» в мини-приложении (или `/admin` в боте) видна только MAX ID из `SUPPORT_MAX_USER_IDS`.

- **Статистика** — `GET /api/v1/admin/overview`: пользователи, активность по дням (приложение и бот, таблица `user_activity`: только день и канал), воронка от анкеты до завершения, регионы, вузы, сценарии, где застревают, качество данных. Команда и тестовые учётки не учитываются.
- **Источники** — фильтр по региону, типу и «не проверялся 90+ дней». «Проверено сегодня» обновляет дату проверки, «Изменить» — ссылку и организацию. Исправленный источник помечается `edited_at` и не перезаписывается данными из JSON при следующем деплое; чтобы вернуть значение из файла, очистите `edited_at`.
- **Отзывы** — новые и разобранные, кнопка «Разобрано» (`resolved_at`).
- Свой MAX ID присылает бот в ответ на команду `/id`.

## Если что-то сломалось

- `GET /health` показывает `bot` (off / polling / webhook / webhook_failed), `database` (ok / unavailable) и `version` — commit запущенной сборки. Им удобно убедиться, что на проде именно сданный commit.
- У каждого ответа есть заголовок `X-Request-ID`. При ошибке 500 интерфейс показывает «Код для поддержки: …» — найдите этот код в Render → Logs, рядом будет полный traceback.
- `python3 tools/run_data_api.py --base-url https://marshrut-tf5o.onrender.com --token <тестовый токен>` — все обязательные проверки API за минуту.
- Откат: Render → сервис → Events → предыдущий deploy → «Rollback».

## Токены и секреты

- В репозитории секретов нет. `MAX_BOT_TOKEN`, `SECRET_KEY`, `WEBHOOK_SECRET`, `TEST_ACCESS_TOKENS`, `DATABASE_URL`, `SUPPORT_MAX_USER_IDS` задаются только в Render → Environment.
- Сменить тестовый токен проверяющих: `python3 -c "import secrets; print(secrets.token_hex(24))"`, в Render записать `<токен>:900000001`.
- Смена `SECRET_KEY` разлогинит всех и отключит выданные ссылки для родителей и календаря.
