# Демо-сценарий

## В MAX (основной)

1. Открыть бота [@t818_hakaton_max_bot](https://max.ru/t818_hakaton_max_bot) в мобильном или веб-клиенте MAX и отправить `/start`.
   Ожидается: приветствие с кнопкой «Открыть маршрут».
2. Нажать «Открыть маршрут». Открывается мини-приложение, экран «Добро пожаловать».
3. «Составить маршрут» → ответы: **Да, гражданин РФ → Москва → Другой вуз → 18 → Очная → В общежитии → Нет → Нет** → «Составить маршрут».
4. Ожидается экран «Ваш маршрут», `0 из 6 выполнено`:
   1. Регистрация по месту пребывания в общежитии — следующий шаг, «желательно до …»
   2. Проверка полиса ОМС
   3. Прикрепление к поликлинике
   4. Студенческий проезд в Москве
   5. Пушкинская карта
   6. Меры поддержки в вузе (по желанию)

   В чате бота приходит «Ваш маршрут готов» с кнопкой «Открыть шаг».
5. Открыть первый шаг. Видны блоки «Почему этот шаг появился?», «Что сделать», «Документы», «Куда обратиться», «Рекомендуемый срок» и «Источник» (метка «Официальный источник», Госуслуги, дата проверки, кнопка открытия).
6. «Отметить выполненным» → открывается следующий шаг, прогресс `1 из 6`, в чат приходит «Следующий шаг».
7. На экране маршрута нажать «Напомнить о следующем шаге в MAX» → в чате появляется напоминание.
8. В чате отправить `/next` → бот присылает текущий следующий шаг. Нажать под ним «✅ Выполнено» → сообщение меняется на «✅ … — выполнено», приходит следующий шаг, прогресс в приложении растёт.
9. В карточке шага со сроком нажать «Добавить в календарь» → скачивается .ics с напоминанием за день.
10. Выполнить оставшиеся шаги → экран «🎉 Маршрут завершён 6 / 6», в чате поздравление.
11. В шаге нажать «Мне это не нужно» → шаг уходит из плана, прогресс считается без него. «План по дням» и «🎒 Что взять с собой» — на экране маршрута, «Если что-то пошло не так» — во вкладке «Помощь».
12. «Изменить ответы и пересобрать маршрут» → например, «Санкт-Петербург», «Снимаю квартиру»: маршрут перестраивается (регистрация через Госуслуги/МФЦ, проездной СПб).

Другие профили для проверки правил:

| Профиль | Ожидаемые шаги |
|---|---|
| Татарстан, 25, очная, общежитие, регистрация есть, поликлиники нет | ОМС, поликлиника, проезд в Казани, поддержка в вузе |
| Новосибирская область (поиск «новосиб»), 18, заочная, общежитие, регистрация есть | ОМС, поликлиника, Пушкинская карта, поддержка в вузе |
| Новосибирская область, 18, очная, снимаю квартиру, регистрации нет | регистрация (источник — МФЦ Новосибирской области), ОМС и поликлиника (ТФОМС НСО), «Студенческий проезд: Новосибирск» (СберТройка) |
| Томская область, 19, очная, общежитие | «Студенческий проезд: Томск» с официальной страницей ТТУ |
| Регион без данных о проезде (например, Чукотский АО), очная | «Студенческий проезд в вашем регионе» — демонстрационная памятка |

После выбора региона анкета показывает, какие официальные данные для него есть (МФЦ, фонд ОМС, студенческий проезд). Шаг «проезд в вашем регионе» и «поддержка в вузе» помечены как «Демонстрационные данные».

## Пилот с вузом

1. Открыть ссылку `https://max.ru/t818_hakaton_max_bot?start=kfu`. Бот пишет, что вы пришли по приглашению КФУ.
2. «Открыть маршрут» → в анкете уже выбраны Татарстан и КФУ.
3. Ответы: 18 → Очная → В общежитии → Нет → Нет. Ожидаемый маршрут: заселение и регистрация в общежитии КФУ, полис ОМС, поликлиника, проезд в Казани, Пушкинская карта, стипендии и материальная поддержка в КФУ — с официальными страницами КФУ.
4. «Пригласить одногруппника» → ссылка на бота с кодом `kfu`.
5. `GET /api/v1/stats` показывает маршрут в разбивке `by_university`.

## Иностранный студент

Ответ «Нет, я иностранный студент» → Москва → Другой вуз → остальные ответы любые, регистрации нет. Маршрут из сценария `foreign_student_v1`: международная служба вуза, миграционный учёт, дактилоскопия и медосвидетельствование, медицинское страхование. Для КФУ — официальные страницы миграционного сопровождения КФУ.

## Проверка API

```bash
python tools/run_data_api.py --base-url https://marshrut-tf5o.onrender.com --token <тестовый токен>
```

Ожидается `13 passed, 0 failed`.

## Локально без MAX

```bash
cp .env.example .env
docker compose up --build
```

Открыть http://localhost:8000 — вход выполняется за development-пользователя, сценарий тот же, что и выше, начиная с шага 2.
